# Programs

Data: `../_shared/data/ma-programs.md` (all records are **leads** until checked on the official page).

## Find
1. Sector strictly: home 1-4 units → residential · apartment 5+ → multifamily · business/office → business.
   Renters are residential but can't take owner-only offers.
2. Utility: Mass Save sponsors are listed in the data file; municipal-utility customers → their light department.
3. Always include the sector's **no-cost assessment** when the cause of high use is unknown.
4. If you can browse: check official sources only (masssave.com, the utility, mass.gov, MassCEC, boston.gov,
   irs.gov, energystar.gov); record URL, date and what it says. Otherwise list "places to check".

## Check
Per lead, mark each condition met / not met / unknown from memory facts →
**Potentially eligible** · **Known condition not met** (say which: "HEAT Loan is for owners; you rent") ·
**More information needed** (the exact question). Pre-approval or participating contractor → "approve **before**
buying" at the top. Always: "Final eligibility and amounts are decided by the program."

## Apply (when the user is ready)
Checklist of what the program page asks for (bills, account numbers, ownership or landlord authorization, quote
with model numbers, qualified-product proof, photos, income documents) - ✓ have / ☐ need. Pre-fill an info sheet
from memory, mask sensitive numbers. Draft the email or form text; **the user submits**.

## Output
3-6 leads grouped: no-cost help · lowers cash now · money back later · financing - each with type, when money
arrives, status and next step. Never quote an amount you didn't read on the official page today; a contractor's
figure is "contractor-reported".

## Memory
Leads with status, source URL and date in `findings.md`; questions in `open-questions.md`; drafts in `documents/`;
`log.md`. Status changes to `applied`/`approved` only when the user reports it (approval needs a reference + date).
